# 「온소리 자막 in YouTube」 0.4.3 · 화면에 새겨진 자막 읽기, 내려받기 재시도

## 바뀐 동작

### 화면에 새겨진 자막을 대사로 사용

- 엑시트 예고편(FjmF3AKHGyM)에서 YouTube 자동 자막을 대사로 쓰자 「구축 순천 입니다 아픈 거 아니오 …」처럼 화면 자막과 전혀 다른 글자가 나왔습니다.<br>음악과 효과음이 큰 예고편에서는 YouTube 자동 자막이 이 PC의 음성 인식보다도 크게 틀렸습니다.
- 영상 전체 분석을 시작하면 소리와 함께 YouTube가 제공하는 소리 없는 화면 영상(360p 안팎)을 받습니다.<br>예고편 80초는 3.4MB였습니다.
- 영상 곳곳에서 16장면을 뽑아 아래쪽에 한국어 자막이 꾸준히 보이는지 확인합니다(장면의 20% 이상, 서로 다른 글 2줄 이상).<br>보일 때만 화면 자막을 대사로 씁니다.
- 0.5초마다 화면 아래쪽 35%(가운데 80%)에서 흰 글자만 남겨 Tesseract 한국어 OCR로 읽습니다.<br>연속된 장면에서 같은 글은 한 줄로 묶고 가장 많이 읽힌 표기를 고릅니다.<br>글자가 바뀌지 않은 장면은 앞의 결과를 다시 씁니다.
- 화면 자막을 못 읽은 순간에는 YouTube 자막 줄로 채웁니다.<br>읽은 줄은 AI 오타 보정도 거칩니다(예: 「점없는 사존동생들」 → 「철없는 사촌동생들」).
- 우선순위는 영상에 올려진 자막 파일, 화면 자막, YouTube 자동 자막, 음성 인식 순서입니다.
- 조작 창 ‘다른 방법’에 **화면에 새겨진 자막을 대사로 사용**을 추가했습니다(기본 켜짐).<br>끄면 화면 영상을 받지 않습니다.
- 화면은 이 기기 안에서만 읽고 저장하거나 보내지 않습니다.<br>개인정보처리방침, 도움말, 스토어 설명에 이 내용을 더했습니다.
- 분석 결과의 `metadata.screen_subtitles`에 사용 여부(used, not-subtitled, no-video, error 등)와 읽은 장면 수를 남깁니다.

### 내려받기가 끊겼을 때

- 0.4.2를 쓰다 분석 상태 칸에 영어 메시지 “Failed to fetch”만 표시된 일이 있었습니다.<br>내려받기 중 연결이 끊기면 브라우저가 내는 메시지가 그대로 나온 것입니다.
- 영상 소리·화면 영상·영상 정보·자막을 받다 연결이 끊기면 1초, 3초 뒤 두 번 다시 시도합니다.<br>그래도 안 되면 “인터넷 연결이 끊겨 YouTube에서 영상 소리를 받지 못했습니다. 연결을 확인하고 다시 시도해 주세요.”처럼 무엇을 받지 못했는지 알립니다.
- AI 모델 파일도 같은 방식으로 다시 시도합니다.<br>연결 문제를 GPU 문제로 보고 CPU로 처음부터 다시 분석하던 동작을 막았습니다.
- 그 밖에 남은 영어 연결 오류는 분석 상태 칸에서 한국어로 바꿔 표시합니다.

### 깨지는 소리 효과음 이름 추가

- 그릇이 깨지는 장면에서 ‘쾅’ 소리는 자막에 나왔지만 깨지는 소리는 나오지 않았다는 팀원 의견이 있었습니다.
- AI 소리 분류 모델(AST)이 깨지고 부서지는 소리에 자주 붙이는 이름 6개가 효과음 목록에 없어, 점수가 기준(25%)을 넘어도 표시할 수 없었습니다.
- Smash, crash(와장창!), Breaking(와장창), Crack(쩍), Clatter(덜그럭), Clang(깡!), Chink, clink(쨍)를 더해 효과음 이름이 82가지에서 88가지가 됐습니다.<br>같은 목록을 쓰는 로컬 서버(`server/lexicon.py`)에도 넣었습니다.
- 처음 제출한 0.4.3의 심사를 11월 25일 취소하고, 이 변경을 넣은 0.4.3 패키지로 다시 제출했습니다.

## 확인 결과

- 확장 검사 194개를 2026-11-24에 실행해 모두 통과했습니다.
- 시험용 Chromium에서 엑시트 예고편을 분석했습니다.<br>화면 자막을 대사로 썼고(「아픈 큰누나」, 「사랑하는 부모님」, 「연로한 친척 어른」, 「철없는 사촌동생들」, 「그리고 나인가?」 등), 전체 분석이 약 90초 걸렸습니다.
- 6분 평가 영상(-wbEQJ_ZXyk)에서는 평가 시트의 화면 자막 45줄 중 37줄을 거의 그대로 읽었고, 전체 분석이 약 6분 걸렸습니다.<br>눈 덮인 장면처럼 배경이 밝은 곳의 자막을 놓쳤습니다.
- 처음에는 장면 하나의 OCR이 1.1초씩 걸렸습니다.<br>화면에 보이지 않는 분석 페이지에서 이미지를 PNG로 바꾸는 단계가 매번 기다렸기 때문이라, 이미지를 직접 만들어 넘기도록 바꿔 0.09초로 줄였습니다.
- 시험 환경에서는 YouTube 자동 자막을 받지 못해, 빈 곳을 자동 자막으로 채우는 동작은 실제 영상으로 확인하지 못했습니다.

## 알려진 한계

- 배경이 밝으면 흰 자막을 놓칠 수 있습니다.
- 로고나 간판 글자가 섞일 수 있습니다(예: 「구름정원」, 「CJ 엔터테인먼트」).
- 예능처럼 강조 자막만 있는 영상은 대사가 아닌 글자를 읽을 수 있습니다.<br>이때는 ‘화면에 새겨진 자막을 대사로 사용’을 끄면 됩니다.
