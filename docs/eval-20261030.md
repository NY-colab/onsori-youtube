## 해석

1. **격리 실행이 실제 Chrome 결과를 재현했다.** 같은 0.3.3 엔진에서 CER·기준 없는 대사 수가 같다. 다만 첫 줄은 `이것은 5시오 이불이요?`(Chrome)와 `이것은 옷이 옷이 입을이요?`(격리)로 달라, 디코딩 경로 차이에 민감하다.
2. **0.3.4 대사 필터:** 음악만 있는 구간의 짧은 상투어(`그러니까`, `뭐야`, `(놀람)` 등) 20개를 제거했고 화면 자막과 겹치는 대사는 하나도 지우지 않았다. 남은 5개의 브라우저 AST Speech 점수는 0.21–0.36으로, 실제 대사 최저 0.395와 가깝다. 영상 1편에 맞춰 기준을 올리지 않았다.
3. **보컬 스템은 대사 인식을 개선하지만 그대로 쓸 수 없다.** CER 0.455→0.334, 환각 16→4. 그러나 실제 대사 `입는 옷이에요.`가 빠졌고, `옷이오` 줄은 여전히 `오시오`로 들렸다. 원본 결과와의 병합 규칙 없이 대체하면 누락이 생긴다. HT-Demucs는 브라우저 기본 경로에서 돌리기 무거우므로 원격·GPU 경로 후보다.
4. **효과음은 스템을 바꾸면 크게 달라진다.** 원본의 숨소리 등 10건이 반주 스템에서 사라지고, 반주에서는 문 닫힘·폭발·경적 등 원본에 없던 사건이 나왔다. 사람 라벨 없이는 어느 쪽이 맞는지 판단하지 않는다.
5. **음악 묘사의 근거가 부족하다.** Python AST 기준 원본 81개 음악 창에서 악기 점수가 묘사 기준 0.2를 넘은 창은 0개, 반주 스템 95개 중 2개였다. 반주 실행이 낸 `클라리넷`·`기타` 3건은 라벨이 없어 채택하지 않는다. 현재의 `♪ 배경 음악이 이어짐`이 근거에 맞는 표현이며, 구체 묘사는 다른 모델을 사람 라벨로 평가한 뒤 판단한다.
6. **`옷이오`류 오류의 근거는 화면 자막이다.** 전체 분석 모드는 화면 프레임을 모으지 않아 이 근거를 쓰지 못한다. 옛말 어미(`가볍소`→`가벼워`)도 같은 근거가 필요하다.
7. 크기: 모든 cue가 표시 중 단일 배율을 쓰며, 끝나지 않은 문장이 이어지면서 배율이 바뀌는 경우는 0건이었다.
